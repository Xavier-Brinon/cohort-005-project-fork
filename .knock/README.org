#+title: Knock workflows
#+options: ^:{}
#+startup: indent

One Knock workflow per Notification type lives here, in the Knock CLI layout
(see =docs/adr/0013-knock-for-in-app-notifications.md=). Each workflow has one
in-app feed step on the =cadence-in-app= channel. Its template holds the
wording; the action URL is always ={{ data.url }}=, which Cadence builds. The
trigger =data= each template reads is typed in =app/lib/notifications.server.ts=
(=NotificationData=).

#+begin_example
knock.json                      # { "knockDir": ".knock" }
.knock/workflows/
├── refund-request-opened/
│   ├── workflow.json           # steps, channel, action URL
│   └── in_app_feed_1/
│       └── markdown_body.md    # the template (Liquid)
└── refund-request-decided/     # branches on data.decision; note only when set
    ├── workflow.json
    └── in_app_feed_1/
        └── markdown_body.md
#+end_example

* Push to Development
Run the CLI from the repository root, so =knock.json= resolves =.knock=. It
needs a login (=knock login=) or a service token in =KNOCK_SERVICE_TOKEN=.

#+begin_src shell
aube dlx @knocklabs/cli whoami
aube dlx @knocklabs/cli workflow validate refund-request-opened
aube dlx @knocklabs/cli workflow push refund-request-opened --environment development --commit -m "Add refund-request-opened"
#+end_src

=--all= pushes every workflow at once. =workflow pull <key>= brings a change
made in the dashboard back into the repo.

* Promote to Production
Promotion is a deliberate, separate step taken by a person, never part of a
push. Knock promotes to the next environment in its chain (Development, QA,
Production), so check the target before you run it:

#+begin_src shell
aube dlx @knocklabs/cli commit promote --to=production
#+end_src
