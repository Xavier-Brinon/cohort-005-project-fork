#+title: Knock workflows
#+options: ^:{}
#+startup: indent

One Knock workflow per Notification type lives here, in the Knock CLI layout
(see =docs/adr/0013-knock-for-in-app-notifications.md=). Each workflow has one
in-app feed step on the =cadence-in-app= channel. Its template holds the
wording; the action URL is always ={{ data.url }}=, which Cadence builds. The
trigger =data= each template reads is typed in =app/lib/notifications.server.ts=
(=NotificationData=).

#+begin_example
knock.json                      # { "knockDir": ".knock" }
.knock/workflows/
├── refund-request-opened/
│   ├── workflow.json           # steps, channel, action URL
│   └── in_app_feed_1/
│       └── markdown_body.md    # the template (Liquid)
├── refund-request-decided/     # branches on data.decision; note only when set
│   ├── workflow.json
│   └── in_app_feed_1/
│       └── markdown_body.md
├── lesson-question-posted/
│   ├── workflow.json
│   └── in_app_feed_1/
│       └── markdown_body.md
└── lesson-reply-posted/        # action URL jumps to #comment-<id>
    ├── workflow.json
    └── in_app_feed_1/
        └── markdown_body.md
#+end_example

* Push to Development
The Knock CLI is a dev dependency. Every script below reads
=KNOCK_SERVICE_TOKEN= from the shell or from =.env= (create the token in the
Knock dashboard, under Settings, Service tokens).

#+begin_src shell
aube run knock:validate                    # Knock validates every workflow, saves nothing
aube run knock:push -- -m "Add a step"     # push and commit every workflow to Development
#+end_src

To push a single workflow, run the CLI itself:

#+begin_src shell
node --env-file-if-exists=.env node_modules/@knocklabs/cli/bin/run.js workflow push refund-request-opened --environment development --commit -m "…"
#+end_src

=workflow pull <key>= brings a change made in the dashboard back into the repo.

* Check for drift
=scripts/knock-workflows.ts= uses the Management API (=@knocklabs/mgmt=) to
check that an environment still holds what the repo says. It validates every
workflow, then compares each field set in =.knock/workflows= with Knock, and
lists any workflow Knock holds that the repo does not. Fields only Knock sets
(=sha=, timestamps, defaults) and trailing whitespace are not drift.

#+begin_src shell
aube run knock:check                                  # against Development
aube run knock:check -- --environment production      # before or after a promote
#+end_src

It exits 1 on any drift, so CI can run it as a gate.

* Promote to Production
Promotion is a deliberate, separate step taken by a person, never part of a
push. Knock promotes to the next environment in its chain (Development, QA,
Production), so check the target before you run it:

#+begin_src shell
aube dlx @knocklabs/cli commit promote --to=production
#+end_src
